title: "Input"
description: "reskate.input: named actions on keys and pad combos, flight keys and mouse look, gamepads, joysticks and radios (all 8 channels, and which controller), raw pad bits, keys and the mouse wheel, keeping the controller or some of its buttons from the game, and whether the game has the input."

`reskate.input` gives your plugin actions the player can press, and reads the keyboard, mouse, gamepad and joystick for a plugin that flies something or runs a game of its own. Every function, and the `action` event, needs the `input` permission; calling one without it raises an error. See [permissions](/plugins/permissions).

## Actions

### `reskate.input.bind(action, key)`

Puts a named action on a key or a pad combo. Each press fires the `action` event with the action's name, once, while the game itself has the input: not while a menu, the console or a text box is open.

The player sees your actions on the **Binds** page of ReSkate's settings and can record another combo for any of them, or clear it. The player's choice wins over yours and is kept between sessions.

<ParamField path="action" type="string" required>The action's name, 1 to 48 characters. It is what the `action` event hands your handler. Binding a name again replaces its combo.</ParamField>
<ParamField path="key" type="string">A key, a key combo, or a pad combo, at most 60 characters (see below). `nil` (or nothing): no key of its own; the action is on the Binds page for the player to put on one.</ParamField>

<ResponseField name="ok" type="boolean">True when the action is bound.</ResponseField>
<ResponseField name="why" type="string">`"that is not a key or pad combo"` when `ok` is false.</ResponseField>

```lua
reskate.input.bind("mark", "F7")
reskate.input.bind("menu", "Ctrl+K")
reskate.input.bind("boost", "Pad.LB+Pad.RB")

reskate.on("action", function(name)
    if name == "mark" then
        reskate.log("marked")
    elseif name == "boost" then
        reskate.skater.boost("forward")
    end
end)
```

A key name that is not one raises an error, as does a 17th action.

<Note>
Needs the `input` permission. A plugin has at most 16 actions. When the plugin stops, its actions go away (the player's choices for them are kept).
</Note>

### Key and pad combo names

A combo is names joined with `+`, with no spaces. Case does not matter. A combo is either keys or pad buttons, never both.

**Keys** (up to 5 held together):

| Name | Key |
| --- | --- |
| `A` to `Z` | Letters |
| `0` to `9` | The number row |
| `F1` to `F12` | Function keys |
| `Space` | Space bar |
| `Ctrl`, `Shift`, `Alt` | Modifiers, alone or in a combo |

Examples: `"F7"`, `"Ctrl+K"`, `"Shift+Alt+1"`, `"Space"`.

**Pad buttons**, each written `Pad.` and the button:

| Name | Button |
| --- | --- |
| `Pad.A`, `Pad.B`, `Pad.X`, `Pad.Y` | Face buttons (Xbox names) |
| `Pad.LB`, `Pad.RB` | Bumpers |
| `Pad.LT`, `Pad.RT` | Triggers, pressed past their dead zone |
| `Pad.Up`, `Pad.Down`, `Pad.Left`, `Pad.Right` | The d-pad |
| `Pad.Start`, `Pad.Back` | Start and Back |
| `Pad.L3`, `Pad.R3` | Stick clicks |

Examples: `"Pad.A"`, `"Pad.LB+Pad.RB"`, `"Pad.Up+Pad.Y"`.

### The `action` event

```lua
reskate.on("action", function(name)
    -- name: the action's name, as you bound it
end)
```

A combo fires once when all of it is held, and again only after it is let go. Registering a handler needs the `input` permission. See [events](/plugins/events).

## Flight input

### `reskate.input.flight()`

The flight keys and the mouse, as Freecam reads them, for a plugin that flies its own camera. It answers only while the plugin's [camera](/plugins/api/camera) view is the one shown, the game window has the focus, and no ReSkate menu is open.

<ResponseField name="input" type="table or nil">
`nil` when the plugin's view is not shown, or the game cannot be read now.
<Expandable title="fields">
<ResponseField name="right" type="number">1 with D, -1 with A, 0 with neither (or both).</ResponseField>
<ResponseField name="up" type="number">1 with E, -1 with Q.</ResponseField>
<ResponseField name="forward" type="number">1 with W, -1 with S.</ResponseField>
<ResponseField name="look_x" type="number">How far the mouse moved right since the last read, in pixels, while the right mouse button is held. 0 otherwise.</ResponseField>
<ResponseField name="look_y" type="number">How far it moved down, in pixels, the same way.</ResponseField>
<ResponseField name="boost" type="boolean">True while Shift is held.</ResponseField>
</Expandable>
</ResponseField>

```lua
local yaw, pitch = 0, 0
reskate.on("tick", function(dt)
    local input = reskate.input.flight()
    if not input then return end
    yaw -= input.look_x * 0.003
    pitch = math.clamp(pitch - input.look_y * 0.003, -1.4, 1.4)
end)
```

The mouse's movement is used up as it is read, and it is read once a tick: two calls in one tick see the same values.

<Note>Needs the `input` permission and a camera view of the plugin's own (`camera.look` or `camera.set`).</Note>

## Controllers

### `reskate.input.gamepad()`

The gamepad's sticks, triggers and buttons. It reads the pad even while the game is kept from it (see `capture`).

<ResponseField name="pad" type="table or nil">
`nil` when no pad is connected or the game window does not have the focus.
<Expandable title="fields">
<ResponseField name="left_x" type="number">The left stick, -1 (left) to 1 (right).</ResponseField>
<ResponseField name="left_y" type="number">The left stick, -1 (down) to 1 (up).</ResponseField>
<ResponseField name="right_x" type="number">The right stick, -1 to 1.</ResponseField>
<ResponseField name="right_y" type="number">The right stick, -1 to 1.</ResponseField>
<ResponseField name="left_trigger" type="number">0 (released) to 1 (pulled all the way).</ResponseField>
<ResponseField name="right_trigger" type="number">0 to 1.</ResponseField>
<ResponseField name="buttons" type="table">A boolean for each button: `up`, `down`, `left`, `right` (the d-pad), `start`, `back`, `left_stick`, `right_stick` (stick clicks), `lb`, `rb`, `a`, `b`, `x`, `y`.</ResponseField>
<ResponseField name="playstation" type="boolean">True for a PlayStation pad. Its buttons keep the Xbox names above.</ResponseField>
</Expandable>
</ResponseField>

```lua
local pad = reskate.input.gamepad()
if pad and pad.buttons.a then
    reskate.log(string.format("left stick %.2f %.2f", pad.left_x, pad.left_y))
end
```

<Note>Needs the `input` permission.</Note>

### `reskate.input.joystick(device)`

A joystick, RC radio or other game controller connected to Windows. With no `device`, one whose name holds "radio", "EdgeTX" or "OpenTX" is chosen first, otherwise the lowest-numbered one.

<ParamField path="device" type="integer">A controller's number from [`joysticks()`](#reskate-input-joysticks), 0 to 15. Leave it out for the first controller as above.</ParamField>

<ResponseField name="stick" type="table or nil">
`nil` when there is no such controller, or the game window does not have the focus.
<Expandable title="fields">
<ResponseField name="axes" type="table">A list of 8 numbers, each -1 to 1: X, Y, Z, Rx, Ry, Rz and the two sliders, which is all 8 channels of a radio. Axes the device does not have read 0.</ResponseField>
<ResponseField name="buttons" type="table">A list of 32 booleans, button 1 first.</ResponseField>
<ResponseField name="name" type="string">The device's name, as Windows gives it.</ResponseField>
<ResponseField name="device" type="integer">The controller's number, as `joysticks()` lists it.</ResponseField>
</Expandable>
</ResponseField>

ReSkate reads the controllers on a thread of its own, about 250 times a second, and this call returns the latest reading, so it never holds up your tick. Just after the first call, or after a controller is plugged in, it can take a moment to show up.

```lua
local stick = reskate.input.joystick()
if stick then
    local throttle = (stick.axes[3] + 1) / 2
end
```

<Note>Needs the `input` permission. Before ReSkate 2.1.3 there were 6 axes, in Windows' older order (X, Y, Z, R, U, V). A plugin that saved which axis is which should let players set them again.</Note>

### `reskate.input.joysticks()`

Every game controller plugged in, so a player with a gamepad and a radio can pick which one your plugin reads.

<ResponseField name="list" type="table">
A list, lowest number first, empty when none is plugged in. Each entry:
<Expandable title="fields">
<ResponseField name="device" type="integer">The controller's number, for `joystick(device)`. It stays the same while the controller stays plugged in.</ResponseField>
<ResponseField name="name" type="string">The device's name, as Windows gives it.</ResponseField>
</Expandable>
</ResponseField>

```lua
for _, controller in ipairs(reskate.input.joysticks()) do
    reskate.log(controller.device .. ": " .. controller.name)
end
local radio = reskate.input.joystick(chosen_device)
```

<Note>Needs the `input` permission.</Note>

### `reskate.input.capture(on)`

Keeps the game from reading the controller, so the player can fly your camera with the pad without the skater moving too. Each call keeps it for 250 ms: call it every tick for as long as you want it. Your plugin still reads the pad with `gamepad()`.

<ParamField path="on" type="boolean" required>True to keep the controller for the next 250 ms, false (or nothing) to give it back now.</ParamField>

<ResponseField name="ok" type="boolean">True when the controller is kept (or given back).</ResponseField>
<ResponseField name="why" type="string">`"only while the plugin's camera is shown"` when `ok` is false.</ResponseField>

```lua
reskate.on("tick", function()
    if flying then
        reskate.input.capture(true)
        local pad = reskate.input.gamepad()
        -- fly with the pad
    end
end)
```

<Note>
Needs the `input` permission. It works only while the plugin's own camera view is shown: when Spectate takes the camera, or the plugin releases it, the game has the controller again at once. One plugin captures at a time: the latest call wins.
</Note>

### `reskate.input.hide(controls)`

Keeps some of the pad's controls from the game, for a plugin that gives them a job of its own, such as picking a grind's exit with the triggers, or aiming a camera of its own with the right stick. A hidden trigger reads to the game as let go, a hidden stick as centred, and a hidden stick click as not pressed. The left stick's left and right, hidden while grinding, read as centred only while the skater grinds, so a push held through the pop reaches the game at the pop. Your plugin still reads them all with `gamepad()`.

<ParamField path="controls" type="table or nil" required>
What to keep from the game. Each call replaces your plugin's last one; `nil` or `{}` gives everything back.
<Expandable title="fields">
<ParamField path="left_trigger" type="boolean">True to hide the left trigger.</ParamField>
<ParamField path="right_trigger" type="boolean">True to hide the right trigger.</ParamField>
<ParamField path="left_x" type="string">`"grinding"` to hide the left stick's left and right while the skater grinds. Any other value raises an error.</ParamField>
<ParamField path="right_stick" type="boolean">True to hide the right stick, both ways.</ParamField>
<ParamField path="left_stick_click" type="boolean">True to hide the left stick's click.</ParamField>
<ParamField path="right_stick_click" type="boolean">True to hide the right stick's click.</ParamField>
</Expandable>
</ParamField>

<ResponseField name="ok" type="boolean">True when the controls are hidden (or given back).</ResponseField>
<ResponseField name="why" type="string">`"hiding pad controls is unavailable for this game build"` when `ok` is false.</ResponseField>

```lua
-- While the skater grinds, the triggers are the plugin's (skater_state needs events.skater).
reskate.on("skater_state", function(state)
    if state == "grinding" then
        reskate.input.hide({left_trigger = true, right_trigger = true, left_x = "grinding"})
    else
        reskate.input.hide(nil)
    end
end)
```

<Note>
Needs the `input` permission. Unlike `capture`, it needs no camera of your own and lasts until you change it. A control stays hidden while any plugin hides it. Your plugin reads the pad once a tick, so the game may see a trigger for a frame before you hide it. When the plugin stops, everything it hid is given back.
</Note>

## Raw input

These read the pad and the keyboard as they are, for a plugin with a game layer of its own: menus it draws, buttons it gives a job, things it places.

### `reskate.input.pad_bits(menu)`

The gamepad's buttons as one number of bits, XInput's own, with the triggers added.

<ParamField path="menu" type="boolean" default="false">True to read the pad while ReSkate's menu, console or a dialog is open too.</ParamField>

<ResponseField name="bits" type="number or nil">The buttons held now. `nil` when no pad is connected, the game window does not have the focus, or (without `menu`) ReSkate's menu is open.</ResponseField>

| Bit | Button |
| --- | --- |
| `0x0001`, `0x0002`, `0x0004`, `0x0008` | The d-pad: up, down, left, right |
| `0x0010`, `0x0020` | Start, Back |
| `0x0040`, `0x0080` | Left and right stick clicks |
| `0x0100`, `0x0200` | Left and right bumpers |
| `0x1000`, `0x2000`, `0x4000`, `0x8000` | A, B, X, Y |
| `0x10000`, `0x20000` | Left and right triggers, pulled past XInput's threshold |

```lua
local was = 0
reskate.on("tick", function()
    local bits = reskate.input.pad_bits() or 0
    local pressed = bit32.band(bits, bit32.bnot(was))
    was = bits
    if bit32.band(pressed, 0x1000) ~= 0 then reskate.log("A pressed") end
end)
```

<Note>Needs the `input` permission.</Note>

### `reskate.input.key(key)`

Whether a key or a mouse button is held down now. It reads past a pause or a capture that keeps the input from the game.

<ParamField path="key" type="string or number" required>
A key's name, or a Windows virtual key code from 1 to 254. The names (case matters):

- `"A"` to `"Z"` and `"0"` to `"9"`
- `"Enter"`, `"Backspace"`, `"Escape"`, `"Tab"`, `"Space"`, `"Delete"`
- `"Shift"`, `"Ctrl"`, `"Alt"`
- `"Home"`, `"End"`, `"PageUp"`, `"PageDown"`
- `"Left"`, `"Up"`, `"Right"`, `"Down"`
- `"["`, `"]"`
- `"LeftMouse"`, `"RightMouse"`, `"MiddleMouse"`
</ParamField>

<ResponseField name="down" type="boolean">True while it is held.</ResponseField>

```lua
if reskate.input.key("Enter") or reskate.input.key("LeftMouse") then
    -- drop the thing being placed
end
```

Another name, a lower-case letter, or a number out of range raises an error.

<Note>
Needs the `input` permission. It does not check that the game window has the focus or that ReSkate's menu is shut: read `focus` (below) for that, so a key pressed in another window or typed into the chat does nothing.
</Note>

### `reskate.input.wheel()`

The mouse wheel's notches since the last call. They are gathered only while game input is paused by `game_buttons` (see below).

<ResponseField name="notches" type="number">Whole notches: above 0 rolled away from the player, below 0 towards. 0 when none, or when game input is not paused.</ResponseField>

```lua
local size = 5
reskate.on("tick", function()
    reskate.input.game_buttons(0, 0, true) -- pause game input while sizing
    size = math.clamp(size + reskate.input.wheel(), 1, 20)
end)
```

<Note>Needs the `input` permission. The notches are used up as they are read, for every plugin together.</Note>

### `reskate.input.mouse()`

How far the mouse moved since your plugin last read it, for a camera of your own that the mouse aims. Unlike `wheel`, it needs no pause: the game still gets the mouse too.

<ResponseField name="motion" type="table or nil">
`nil` while the game window is not in front, or ReSkate's menu, console or a dialog is open. Movement in that time is thrown away, so nothing piles up for when it closes.
<Expandable title="fields">
<ResponseField name="x" type="number">The mouse's raw counts to the right since your last read (negative: to the left).</ResponseField>
<ResponseField name="y" type="number">Its raw counts down (negative: up).</ResponseField>
<ResponseField name="wheel" type="number">The wheel's notches: above 0 rolled away from the player, below 0 towards.</ResponseField>
</Expandable>
</ResponseField>

```lua
-- Turn a camera of your own with the mouse.
local yaw, pitch = 0, 0
reskate.on("tick", function()
    local m = reskate.input.mouse()
    if m then
        yaw = yaw + m.x * 0.003
        pitch = math.clamp(pitch - m.y * 0.003, -1.4, 1.4)
    end
end)
```

<Note>Needs the `input` permission. Each plugin gets all the movement: reading it does not take it from another plugin. Your first read gives only the latest movement, and a plugin that has not read for 2 seconds starts again that way.</Note>

### `reskate.input.text(capture)`

What the player typed since the last call, while one of your plugin's screens is open: for a text field your plugin draws itself on a [screen with no panel](/plugins/api/menu#full-screen-screens).

<ParamField path="capture" type="boolean" default="true">True (or nothing) to keep taking the typing for 300 ms more: call it every frame while your field types. While it does, Esc is your plugin's (read it with `reskate.input.key`) and does not close the screen. False lets go at once.</ParamField>

<ResponseField name="typed" type="string">The characters typed, in UTF-8, printable ones only: no Enter, Backspace, Tab or arrows (read those with `reskate.input.key`). `""` when none were, and always while none of your screens is open. At most 1024 bytes wait between calls.</ResponseField>

```lua
-- A one-line field: what is typed goes in at the end, Backspace takes one off, Enter keeps it.
local name, typing, backspace_was = "", false, false
reskate.on("draw", function(d)
    if not typing then return end
    name ..= reskate.input.text(true)
    if reskate.input.key("Backspace") and not backspace_was then name = string.sub(name, 1, utf8.offset(name, -1) - 1) end
    backspace_was = reskate.input.key("Backspace")
    if reskate.input.key("Enter") then
        typing = false
        reskate.input.text(false)
    end
    d:text(vector.create(100, 100, 0), name .. "|", {size = 24})
end)
```

<Note>Needs the `input` permission. There is no clipboard: a field cannot paste.</Note>

### `reskate.input.cursor()`

The mouse over the game window while one of your plugin's screens is open: for a tool on a [docked screen](/plugins/api/menu#full-screen-screens) that picks or drags things the player sees.

<ResponseField name="cursor" type="table or nil">
`nil` while none of your screens is open.
<Expandable title="fields">
<ResponseField name="position" type="vector">Where the mouse is, in pixels from the window's top left, as the overlay's screen shapes place them.</ResponseField>
<ResponseField name="left" type="boolean">True while the left button is held. Also `right` and `middle`.</ResponseField>
<ResponseField name="wheel" type="number">The wheel's notches since your last read: above 0 rolled away from the player.</ResponseField>
<ResponseField name="over_screen" type="boolean">True while the mouse is over your screen's own panel, where its widgets take the clicks.</ResponseField>
</Expandable>
</ResponseField>

```lua
-- Pick the nearest of the points drawn last frame with a left click beside the panel.
local was_down = false
reskate.on("tick", function()
    local c = reskate.input.cursor()
    if c and not c.over_screen and c.left and not was_down then
        pick_near(c.position)
    end
    was_down = c ~= nil and c.left
end)
```

<Note>Needs the `input` permission.</Note>

### `reskate.input.game_buttons(hidden, held, pause)`

Keeps pad buttons from the game, for a plugin that gives them a job, and pauses all game input for a moment. Your plugin still reads every button with `pad_bits` and `gamepad`.

<ParamField path="hidden" type="number" default="0">A mask of the button bits above, `0` to `0xFFFF`: these read to the game as let go. The triggers are not in it: hide them with `hide`.</ParamField>
<ParamField path="held" type="number" default="0">A mask, `0` to `0xFFFF`, of the buttons the player still holds. While a button is in both `hidden` and `held`, the game reads no input at all, as during a pause: the game does not see a button you took until it is let go.</ParamField>
<ParamField path="pause" type="boolean" default="false">True to pause all of the game's input for 500 ms from now. Call it every tick for as long as you want it. False does not end a pause early.</ParamField>

Returns nothing. Each call replaces both masks.

```lua
-- While placing, the d-pad is the plugin's; the game never sees it.
reskate.on("tick", function()
    if placing then
        local dpad = 0x000F
        local bits = reskate.input.pad_bits() or 0
        reskate.input.game_buttons(dpad, bit32.band(bits, dpad), false)
    else
        reskate.input.game_buttons(0, 0, false)
    end
end)
```

A mask that is not a number from 0 to 0xFFFF raises an error.

<Note>
Needs the `input` permission. One set of masks is kept for every plugin: the latest call wins. The masks last until you change them; when the plugin that called last stops, they are cleared. Unlike `capture`, it needs no camera of your own.
</Note>

### `reskate.input.game_keys(keys)`

Keeps keys from the game, for a plugin that gives them a job where the game would use them too: Q and E, which step the game's tabs in its menus, say. The game does not see these keys go down, by any of the ways it reads the keyboard. Their releases still reach it, so a key it saw go down before still comes up. Your plugin still reads them with `key`.

<ParamField path="keys" type="table">A list of at most 32 keys, each a name or a virtual key code as `key` takes them. `nil` or `{}` gives every key back.</ParamField>

Returns nothing. Each call replaces the list.

```lua
-- While the plugin's own tabs show over an item grid, Q and E step them, not the game's.
reskate.on("tick", function()
    if over_grid and my_tabs then
        reskate.input.game_keys({"Q", "E"})
    else
        reskate.input.game_keys(nil)
    end
end)
```

A list of more than 32 keys, a name that is not one, `"Escape"` or a mouse button raises an error: Escape and the mouse always reach the game.

<Note>
Needs the `input` permission. One list is kept for every plugin: the latest call wins. It lasts until you change it; when the plugin that called last stops, the keys are given back.
</Note>

## Who has the input

### `reskate.input.allowed()`

Whether the game has the input now: its window has the focus, ReSkate's menu, console and dialogs are shut, and the game lets gameplay input through.

<ResponseField name="allowed" type="boolean">True when all three hold. It is `focus().focused and not focus().interface_open and focus().gameplay`.</ResponseField>

```lua
if reskate.input.allowed() and reskate.input.key("F") then
    -- finish placing
end
```

<Note>Needs the `input` permission.</Note>

### `reskate.input.focus()`

The three checks behind `allowed`, one by one.

<ResponseField name="focus" type="table">
<Expandable title="fields">
<ResponseField name="focused" type="boolean">True while the game window has the focus.</ResponseField>
<ResponseField name="interface_open" type="boolean">True while ReSkate's menu, console or a dialog has the input.</ResponseField>
<ResponseField name="gameplay" type="boolean">True while the game lets gameplay input through: false during a load, in the game's own menus, and while the native throwdown match panel is open.</ResponseField>
</Expandable>
</ResponseField>

```lua
local f = reskate.input.focus()
if f.focused and not f.interface_open then
    -- read keys for the plugin's own screen
end
```

<Note>Needs the `input` permission.</Note>

<Tip>
The [flying camera guide](/plugins/guides/flying-camera) puts `camera.set`, `input.flight`, `input.gamepad` and `input.capture` together.
</Tip>
