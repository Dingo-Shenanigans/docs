---
title: "Progression and settings"
description: "reskate.progression and reskate.settings: read the player's progress, read the game's settings or hold one at a value of yours, and hold a gameplay option for a moment."
---

These tables read the player's progress in the game and the game's own settings. Nothing here changes the profile. A plugin can hold a game setting at a value of its own while it runs, and the setting goes back to what it was after.

- `reskate.progression.get` needs the `progression.read` permission.
- `reskate.settings.game`, `reskate.settings.names` and `reskate.settings.gameplay` need the `settings.read` permission.
- `reskate.settings.set` and `reskate.settings.hold_gameplay` need the `settings.write` permission.

Calling a function without its permission raises an error. See [permissions](/plugins/permissions).

## Progression

### `reskate.progression.get()`

The local player's progress, as their profile has it.

<ResponseField name="progress" type="table or nil">
`nil` when the profile's progress cannot be read now.
<Expandable title="fields">
<ResponseField name="districts" type="table">A list of districts. Each has `id` (string), `name` (string) and `rank` (integer): the player's rank there.</ResponseField>
<ResponseField name="challenges" type="table">
A list of challenges. Each has:
<Expandable title="fields">
<ResponseField name="id" type="string">The challenge's id.</ResponseField>
<ResponseField name="type" type="string">Its type.</ResponseField>
<ResponseField name="neighborhood" type="string">The id of the district it is in; may be empty.</ResponseField>
<ResponseField name="attempts" type="integer">How many times the player tried it.</ResponseField>
<ResponseField name="completed_goals" type="integer">How many of its goals the player completed.</ResponseField>
<ResponseField name="goal_count" type="integer">How many goals it has.</ResponseField>
</Expandable>
</ResponseField>
<ResponseField name="score" type="number">The player's score.</ResponseField>
<ResponseField name="score_cap" type="number">The score's cap.</ResponseField>
<ResponseField name="score_level" type="integer">The player's score level.</ResponseField>
</Expandable>
</ResponseField>

```lua
local progress = reskate.progression.get()
if progress then
    local done = 0
    for _, c in progress.challenges do
        if c.goal_count > 0 and c.completed_goals == c.goal_count then done += 1 end
    end
    reskate.log(string.format("%d of %d challenges complete", done, #progress.challenges))
    for _, d in progress.districts do
        reskate.log(d.name .. ": rank " .. d.rank)
    end
end
```

<Note>Needs the `progression.read` permission.</Note>

## Settings

The game's engine settings, by name, as the console shows them.

### `reskate.settings.game(name)`

A setting's value now.

<ParamField path="name" type="string" required>The setting's name, as `names()` lists it. At most 120 characters; longer raises an error.</ParamField>

<ResponseField name="value" type="string or nil">The value as the console shows it, or `nil` for a name there is none of, or a value that cannot be read now. Numbers come back as text: use `tonumber`.</ResponseField>

```lua
for _, name in reskate.settings.names() do
    if string.find(name, "Fov", 1, true) then
        reskate.log(name .. " = " .. tostring(reskate.settings.game(name)))
    end
end
```

<Note>Needs the `settings.read` permission.</Note>

### `reskate.settings.names()`

Every setting name known so far: those listed from the engine's settings this session, and those remembered from earlier ones.

<ResponseField name="names" type="table">A list of strings.</ResponseField>

<Note>Needs the `settings.read` permission.</Note>

### `reskate.settings.set(name, value)`

Holds a game setting at a value of yours for as long as your plugin keeps it. When you let go, or your plugin stops, the setting goes back to the value it had when you first set it, unless something else has changed it since: then it stays as that left it.

<ParamField path="name" type="string" required>The setting's name, as `names()` lists it. At most 120 characters; longer raises an error.</ParamField>
<ParamField path="value" type="string, number, boolean or nil" required>The value, as the console takes it: text of at most 200 characters, a number, or `true` and `false`. `nil` lets go.</ParamField>

<ResponseField name="ok" type="boolean">True when the setting holds your value (or you let go).</ResponseField>
<ResponseField name="why" type="string">
When `ok` is false:
- `"no game setting is called \"<name>\""`.
- `"<plugin> holds <name>"`: another plugin set it first.
- `"<name> changes how the game plays, so it cannot be changed during a multiplayer session"`.
- `"a plugin holds at most 32 settings"`.
- `"sound settings are the player's: no plugin changes how loud the game is"`: a setting whose name says volume, audio, sound, mute, loud, speaker, voip, voice, sfx or dynamic range.
- The game's own reason, for a value the setting cannot take.
</ResponseField>

```lua
-- Every field-of-view setting held at 90 while the plugin runs; each goes back when it stops.
for _, name in reskate.settings.names() do
    if string.find(name, "Fov", 1, true) then
        local ok, why = reskate.settings.set(name, 90)
        if not ok then reskate.log(name .. " unchanged: " .. why, "warn") end
    end
end
```

<Note>
Needs the `settings.write` permission. During a multiplayer session, settings that change how the game plays are refused, as they are from the console: those of the `SimulationTime`, `Physics`, `PhysicsQuality`, `FBCorePhysics`, `DingoGameplay`, `DingoActivity`, `DingoThrowdowns`, `DingoThrowdown`, `DelMarGame`, `AutoPlayers` and `SkaterRecord` groups. One your plugin held before the session goes back when it starts. Letting go of a setting you do not hold does nothing.
</Note>

## Gameplay options

The player's on and off gameplay preferences, as the game reads them while you play. A plugin can hold one at a value of its own for a moment, such as a controller layer that needs a preference set one way while its scheme runs. Nothing is saved: the player's profile, and the game's own **Settings** screen, keep the player's value.

An option is known by the name the game reads it by. A name is known only once the game has read that option this session; before that, `gameplay` returns `nil` and `hold_gameplay` refuses it.

### `reskate.settings.gameplay(name)`

The player's own value of a gameplay option, whatever a plugin holds.

<ParamField path="name" type="string" required>The option's name, 1 to 120 characters, with no zero byte. Anything else raises an error.</ParamField>

<ResponseField name="value" type="boolean or nil">The player's value. `nil` until the game has read that option.</ResponseField>

<Note>Needs the `settings.read` permission.</Note>

### `reskate.settings.hold_gameplay(name, value)`

Holds a gameplay option at `value` for the next 300 ms, as the game reads it during play.

<ParamField path="name" type="string" required>The option's name, 1 to 120 characters, with no zero byte.</ParamField>
<ParamField path="value" type="boolean or nil" required>`true` or `false`. `nil` lets go of your hold.</ParamField>

<ResponseField name="ok" type="boolean">True when the option holds your value (or you let go).</ResponseField>
<ResponseField name="why" type="string">
When `ok` is false:
- `"gameplay input is unavailable"`: the game window does not have the focus, ReSkate's menu is open, or the game holds gameplay input.
- `"the host has turned boosts off"`, in a session whose host turned boosts off, or `"not while a throwdown runs"` (unless the game's stock physics is on, as a game mode has it).
- `"this boolean gameplay option has not been read by the game yet"`.
- `"<plugin> holds this gameplay option"`: another plugin's hold is live.
- `"at most 32 gameplay options per plugin"`.
</ResponseField>

```lua
-- Keep an option off while the plugin's control scheme runs.
reskate.on("tick", function()
    if scheme_on then reskate.settings.hold_gameplay(option_name, false) end
end)
```

<Note>
Needs the `settings.write` permission. A hold lasts 300 ms: call it every tick to keep it. One plugin holds each option at a time, and a plugin holds at most 32 at once. The trainer's own overrides come first. While the player is changing settings in the game's menu, the game reads the player's value. A name that is not 1 to 120 characters, or a value that is not a boolean or `nil`, raises an error. Letting go always works, and when the plugin stops its holds end.
</Note>
