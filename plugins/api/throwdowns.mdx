`reskate.throwdowns` reads the throwdown the local player is in, hosts drops for chosen players of the session, and holds the throwdown kit: the functions that make a throwdown mode a plugin. Every function, the `throwdown` event and the `throwdown_ui` event need the `throwdowns` permission; calling a function without it raises an error. See [permissions](/plugins/permissions).

## Reading and hosting drops

### `reskate.throwdowns.state()`

The throwdown the local player is in, if any.

<ResponseField name="state" type="table">
<Expandable title="fields">
<ResponseField name="active" type="boolean">True while a throwdown runs for the local player.</ResponseField>
<ResponseField name="host" type="boolean">True when the local player hosts it.</ResponseField>
<ResponseField name="skate" type="table">
While a game of S.K.A.T.E. is shown, its players in order; otherwise an empty list. Each entry:
<Expandable title="fields">
<ResponseField name="name" type="string">The player's name.</ResponseField>
<ResponseField name="letters" type="integer">How many letters of S.K.A.T.E. they have.</ResponseField>
<ResponseField name="up" type="boolean">True when it is their turn.</ResponseField>
<ResponseField name="out" type="boolean">True when they are out.</ResponseField>
</Expandable>
</ResponseField>
</Expandable>
</ResponseField>

```lua
local t = reskate.throwdowns.state()
for _, p in t.skate do
    reskate.log(string.format("%s: %d letter(s)%s", p.name, p.letters, p.out and ", out" or ""))
end
```

<Note>Needs the `throwdowns` permission.</Note>

### `reskate.throwdowns.host(mode, players, options)`

Hosts a drop where the local skater stands, shown only to the players you choose. They see it in their game and join it with the game's own Join; it starts once all of them have joined. The drop spawns over the next moments: follow it with `hosting()`.

<ParamField path="mode" type="string" required>`"jam"` (a jam session), `"spot_battle"` or `"skate"` (S.K.A.T.E.). The game's own names, `"JamSession"`, `"SpotBattle"` and `"ThrowdownSkate"`, work too.</ParamField>
<ParamField path="players" type="table" required>A list of 1 to 7 other players of the session: ids (`"7656..."`) or player tables with an `id`, as `reskate.session.players()` gives them. A player listed twice counts once.</ParamField>
<ParamField path="options" type="table">
<Expandable title="fields">
<ParamField path="max" type="integer" default="the players, plus you">2 to 8 players in the drop. It is never less than the chosen players plus you.</ParamField>
</Expandable>
</ParamField>

<ResponseField name="ok" type="boolean">True when the drop was asked for.</ResponseField>
<ResponseField name="why" type="string">Why not: `"one drop every 5 s"`, `"not in a session"`, `"<plugin> is hosting a drop"` (another plugin's drop is being asked for, spawning or open) or `"a drop is asked for already"`.</ResponseField>

```lua
local others = {}
for _, p in reskate.session.players() do
    if not p.me then table.insert(others, p) end
end
if #others > 0 then
    local ok, why = reskate.throwdowns.host("skate", others, {max = 4})
    if not ok then reskate.log("no drop: " .. why) end
end
```

An unknown mode, a list of no players or more than 7, a player that is not an id, or a `max` out of range raises an error.

<Note>
Needs the `throwdowns` permission. One drop every 5 seconds; a refused call counts too. Reading the session's players needs `session.read`.
</Note>

### `reskate.throwdowns.hosting()`

What became of this plugin's drop.

<ResponseField name="status" type="string or nil">
`nil` when the plugin has not hosted a drop, or another plugin has hosted one since. Otherwise one of:

- `"asked"`: asked for; it spawns at the next moment it can.
- `"spawning"`: being spawned where the skater stood.
- `"open"`: the chosen players can see it and join it.
- `"started"`: everyone joined, and it runs.
- `"cancelled"`: the plugin cancelled it. It stays so until the plugin's next drop.
- Why it failed: `"the skater is not in the world"`, `"a throwdown or challenge is running"`, `"a chosen player is not in the session"`, `"the throwdown events are not found yet; try again in a moment"`, `"your game is out of linked throwdowns (its speed or mods)"`, `"a plugin's drop is spawning already"`, `"the drop could not be queued"`, `"the drop never spawned"`, `"the drop did not spawn"` or `"the drop could not be described to the other players"`.

</ResponseField>

```lua
reskate.time.every(1000, function()
    local status = reskate.throwdowns.hosting()
    if status then reskate.log("drop: " .. status) end
end)
```

<Note>Needs the `throwdowns` permission.</Note>

### `reskate.throwdowns.cancel()`

Takes this plugin's drop away, if it has not started yet. A drop that started runs on. Cancelling when the plugin has no drop does nothing. After a cancel, `hosting()` says `"cancelled"` (from the next tick) until the plugin hosts another drop.

Returns nothing.

<Note>Needs the `throwdowns` permission. When the plugin stops, its drop is cancelled the same way.</Note>

## The throwdown kit

The throwdown kit makes a throwdown mode a plugin. ReSkate knows no particular mode. Your plugin:

1. Registers its modes with `reskate.throwdowns.mode`. Each gets a card on the game's **Throwdowns** page.
2. Publishes documents with `reskate.throwdowns.ui`: what the player should see. ReSkate draws them with skate.'s own widgets: the setup page, the start flag, the waiting card, the in-game HUD and the match panel.
3. Hears what the player does as [`throwdown_ui` events](#the-throwdown_ui-event), and runs the rules itself.

A mode goes through these steps:

1. The player clicks your card. ReSkate begins the [native flag](#the-native-flag) for the mode and opens Spot Battle's setup page, relabelled from your `setup` document. You hear `open`.
2. The player changes rows (`setup_row`, `setup_button`) and presses Confirm (`setup_confirm`), or backs out (`setup_back`).
3. The player places the start flag with the game's own placement (`flag_placed`). Your `waiting` document becomes the waiting card.
4. The host presses Start (`start`). You drop the `waiting` document and publish your `hud`. The flag in the world goes; the match is yours to run.
5. The match ends. You stop publishing the HUD and call `reskate.throwdowns.flag.leave()`.

A plugin's documents only drive its own modes, and its events only reach it. When the plugin stops, its modes, its documents and its native flag go. For a walkthrough, see [game modes](/plugins/guides/game-modes#a-throwdown-mode-with-the-kit).

## Registering a mode

### `reskate.throwdowns.mode(mode)`

Puts a mode on the **Throwdowns** page, or updates it: calling it again with the same `id` changes that mode. The page shows the stock S.K.A.T.E., Spot Battle and Skate Jam cards (less any a mode replaces), then every plugin's modes by `order`.

<ParamField path="mode" type="table" required>
<Expandable title="fields">
<ParamField path="id" type="string" required>1 to 32 characters, without `/`. Unique in your plugin. Documents and events name the mode by it.</ParamField>
<ParamField path="name" type="string" required>The card's name, 1 to 32 characters.</ParamField>
<ParamField path="description" type="string">The card's text, at most 240 characters.</ParamField>
<ParamField path="art" type="string" default="the stock card's art">The card's logo: the path of a texture or image asset your mod adds, at most 256 characters.</ParamField>
<ParamField path="color" type="number" default="one picked from the id">The card's tint, as `0xAABBGGRR` (0 to 4294967295). `0` picks one from the id.</ParamField>
<ParamField path="card" type="string" default="spot">The stock card it is drawn like: `"skate"`, `"spot"` or `"jam"` (`"spot_battle"` works for `"spot"`).</ParamField>
<ParamField path="replaces" type="string">A stock card whose place it takes: `"skate"`, `"spot"` or `"jam"`. Left out, the mode comes after the stock cards. When two modes replace the same card, the first by `order` takes its place and the other comes after the stock cards.</ParamField>
<ParamField path="order" type="integer" default="0">Its place among the plugin modes, lowest first.</ParamField>
<ParamField path="flag" type="string" default="Spot Battle's">The placement preview its start flag shows: an asset path of your mod, at most 256 characters of letters, digits, `_`, `-`, `.` and `/`.</ParamField>
<ParamField path="cursor_height" type="number" default="0">0 to 100000 metres. Above 0, the flag's placement cursor may rise this far onto things; 0 keeps the game's own ceiling.</ParamField>
<ParamField path="players" type="table">
<Expandable title="fields">
<ParamField path="min" type="integer" default="1">At least 1.</ParamField>
<ParamField path="max" type="integer" default="6">At most 10, and no less than `min`.</ParamField>
<ParamField path="default" type="integer" default="4, or max when that is less">The players the card's flag begins with. Kept between `min` and `max`.</ParamField>
</Expandable>
Left out, the mode has 1 to 6 players, 4 by default.
</ParamField>
</Expandable>
</ParamField>

<ResponseField name="ok" type="boolean">True when the mode is on the page.</ResponseField>
<ResponseField name="why" type="string">Why not: `"a mode needs an id of 1 to 32 characters, without /"`, `"a mode needs a name of 1 to 32 characters"`, `"a description is at most 240 characters"`, `"players are 1 to 10, min no more than max"` or `"32 modes are registered already"` (by all plugins together).</ResponseField>

```lua
local ok, why = reskate.throwdowns.mode{
    id = "duel",
    name = "Duel",
    description = "Beat the last total. Three misses and you're out.",
    card = "spot",
    color = 0xff3434ff,
    order = 10,
    players = {min = 1, max = 6, default = 2},
}
if not ok then reskate.log("no Duel: " .. why) end
```

A `card` or `replaces` that is not a stock card, a `color` or `cursor_height` out of range, an `art` or `flag` over 256 characters, a `flag` with other characters, or a field of the wrong type raises an error.

<Note>Needs the `throwdowns` permission. The mode's setup page comes from your `setup` document, not from this table.</Note>

### `reskate.throwdowns.remove_mode(id)`

Takes one of your modes off the page.

<ParamField path="id" type="string" required>The mode's `id`. An id you never registered does nothing.</ParamField>

Returns nothing.

```lua
reskate.throwdowns.remove_mode("duel")
```

<Note>Needs the `throwdowns` permission. When the plugin stops, all its modes go.</Note>

## Documents

### `reskate.throwdowns.ui(doc)`

Publishes your plugin's documents: what the native UI shows for your modes. Each call replaces everything you published before, so a part you leave out shows nothing. Publish whenever something changes; every tick is fine, since an unchanged document costs only a comparison.

<ParamField path="doc" type="table" required>
<Expandable title="fields">
<ParamField path="setup" type="table">[The setup page](#the-setup-page).</ParamField>
<ParamField path="waiting" type="table">[The waiting card](#the-waiting-card).</ParamField>
<ParamField path="hud" type="table">[The in-game HUD](#the-hud).</ParamField>
<ParamField path="panel" type="table">[The match panel](#the-match-panel).</ParamField>
<ParamField path="flags" type="table">[Your flags, for other players](#flags-for-other-players).</ParamField>
<ParamField path="match" type="table">[What a running match asks of the game](#what-a-match-asks-of-the-game).</ParamField>
</Expandable>
</ParamField>

<ResponseField name="ok" type="boolean">True when the documents are taken.</ResponseField>
<ResponseField name="why" type="string">Why not: `"a throwdown document is at most 512 KB as JSON"`.</ResponseField>

```lua
reskate.on("tick", function()
    local ok, why = reskate.throwdowns.ui({waiting = {mode = "duel", title = "DUEL", enrolled = 1, capacity = 2, can_start = true}})
    if not ok then reskate.log("documents refused: " .. why) end
end)
```

A table that cannot become JSON raises an error: one with keys that are neither a list (1 to n) nor strings, a NaN or infinite number, or tables nested deeper than 32.

The documents are read leniently:

- A field that is missing, or of the wrong type, takes its default. A typo blanks a label, not the whole HUD.
- A text past its limit is cut. Unless a field says otherwise, a text is at most 256 characters. A text may be a number or a boolean; it is shown as Lua prints it.
- A list past its limit keeps its first items. Some widgets show fewer than a list may hold; each field says so.
- `mode` is your mode's own `id` (`"duel"`).
- Colours are `0xAABBGGRR`. Times are milliseconds.
- Positions are world metres: a vector, a list `{x, y, z}` or a table `{x = .., y = .., z = ..}`. A component that is not finite, or past 1 000 000, is 0.
- Steam IDs are strings (`"7656..."`): a Lua number cannot hold every one exactly.

<Note>Needs the `throwdowns` permission. When the plugin stops, its documents go.</Note>

#### Sliders

`players`, `timer` and a `"slider"` row take the same fields.

<ParamField path="slider" type="table">
<Expandable title="fields">
<ParamField path="caption" type="string">Its caption, at most 64 characters.</ParamField>
<ParamField path="min" type="number" default="0">Its least value.</ParamField>
<ParamField path="max" type="number" default="min">Its greatest value.</ParamField>
<ParamField path="step" type="number" default="1">Its step.</ParamField>
<ParamField path="value" type="number" default="min">Its value, kept between `min` and `max`.</ParamField>
</Expandable>
</ParamField>

The page shows whole numbers: `min`, `max` and `value` are rounded, and a step is at least 1. When your document's `value` changes, the slider moves to it. The players slider is 1 to 10 players. The native flag takes the timer's value as its time, kept within 1 to 3600 seconds: a timer of 0 (none) still opens the setup page, and your plugin runs its own clock.

```lua
reskate.throwdowns.ui({setup = {
    mode = "gates", title = "GATES", description = "Skate through the gates. First to the finish wins.",
    players = {caption = "Players", min = 1, max = 8, step = 1, value = 4},
    timer = {caption = "Finish deadline", min = 30, max = 600, step = 30, value = 180},
    rows = {
        {id = "laps", kind = "choice", caption = "Laps", options = {"1", "2", "3"}, value = 1},
        {id = "boost", kind = "slider", caption = "Boost", min = 0, max = 5, step = 1, value = 2},
        {id = "route", kind = "button", caption = "Route", label = "Place gates"},
        {id = "note", kind = "info", caption = "Area", label = "Anywhere"},
    },
}})
```

<Warning>A choice's `value` in the document counts from 1, but its `setup_row` event counts from 0. With the options above, picking `"2"` sends `setup_row` with `{"laps", "1"}`.</Warning>

### The HUD

`hud` is the in-game HUD of a running match, built from slots of skate.'s native HUD. Every slot is optional. Only one plugin's HUD shows at a time.

Many slots draw with a widget family named by `theme`: the widgets `UI/ReSkate/Throwdowns/HUD_<theme>_<part>_Widget` that your mod's data brings (`Title_<width>`, `Score`, `Rank`, `Name_<width>`, `Value_<width>`, `Elapsed`, `Position_<Medal>`, `Warning`, `Logo`, `Results_<width>` and so on). Fields ending in `_art` name another family for one slot. A slot whose widget is not loaded is left out; the others still draw. The clock, the countdown, the banner, the callout, the card and the markers use skate.'s stock widgets.

What shows together:

- While `results` is there, it replaces the header, counters, clock, board and every other slot. The intro, countdown and blackout still show.
- While `editor` is there, the counters, clock, board, position, timers, card and list are hidden.
- While `blackout` is there, the markers are hidden.

<Expandable title="the top fields">

<ParamField path="layout" type="string" default="side">Where the board sits: `"side"` (the right edge) or `"bottom"` (bottom right).</ParamField>
</Expandable>
</ParamField>

#### Clocks

`clock`, `countdown`, a row's `clock` and a timer's `text` or `clock` take a clock. The HUD ticks a clock itself between your documents, from the moment its numbers were true. A clock comes in two forms.

A countdown, or a time counting up to a cap:

<ParamField path="clock" type="table">
<Expandable title="fields">
<ParamField path="remaining_ms" type="number">The time on the clock at `sampled_ms`.</ParamField>
<ParamField path="total_ms" type="number">The whole time. Counting up, the cap (0: none).</ParamField>
<ParamField path="sampled_ms" type="number">`reskate.time.now()` when `remaining_ms` was true. Without it the clock does not move.</ParamField>
<ParamField path="ticking" type="boolean" default="true">False holds the clock still.</ParamField>

## The native flag

One native flag registration exists at a time, for one plugin mode. It runs from the setup page through the game's own flag placement to the waiting card, until your plugin starts the match or the owner leaves. Clicking your card begins it with the mode's default players and opens the setup page, then sends `open`: you do not need to call `flag.begin` for that.

### `reskate.throwdowns.flag.begin(mode, game, options)`

Begins the native flag for one of your modes, without the card.

<ParamField path="mode" type="string" required>Your mode's `id`.</ParamField>
<ParamField path="game" type="number" required>Your number for this game: a whole number from 1 to 4294967295. Events about the flag carry it.</ParamField>
<ParamField path="options" type="table">
<Expandable title="fields">
<ParamField path="players" type="number" default="4">1 to 10.</ParamField>
<ParamField path="seconds" type="number" default="120">The match's time, 1 to 3600. Anything else raises an error.</ParamField>
<ParamField path="setup_page" type="boolean" default="true">False goes straight to flag placement.</ParamField>
<ParamField path="cursor_height" type="number" default="0">0 to 100000 metres, as the mode's `cursor_height`.</ParamField>
</Expandable>
</ParamField>

<ResponseField name="begun" type="boolean">True when the registration began, or waits for the last one to finish going. False while another registration is busy (a flag being placed or down), outside a level, or with options out of range.</ResponseField>

```lua
-- Place this mode's start flag again, straight to placement.
local state = reskate.throwdowns.flag.state()
if state.mine and state.waiting then
    reskate.throwdowns.flag.begin(state.mode, state.game, {players = 6, seconds = 180, setup_page = false})
end
```

With `setup_page = false` while the same mode and game wait on a placed flag, the old flag goes and placement opens again; you do not hear `flag_left` for the old one.

A mode id that is empty, over 32 characters or has `/`, a `game` that is not a whole number in range, or an option out of range raises an error.

<Note>Needs the `throwdowns` permission.</Note>

<Expandable title="fields">

<ResponseField name="owned" type="boolean">True while it holds the game's flag: being set up, placed, or down with the waiting card. False once its flag has given way to the match.</ResponseField>
<ResponseField name="placing" type="boolean">True while the flag is being placed.</ResponseField>
<ResponseField name="waiting" type="boolean">True while the waiting card is up.</ResponseField>
<ResponseField name="mine" type="boolean">True when it is one of your modes.</ResponseField>
<ResponseField name="mode" type="string or nil">Your mode's `id`, only when `mine`.</ResponseField>
<ResponseField name="game" type="number or nil">Its game number, only when `mine`.</ResponseField>
</Expandable>

### `reskate.throwdowns.flag.leave()`

Lets the registration go: you refused it, finished the match or cancelled it. It only acts on a registration of one of your modes. You do not hear `flag_left` for it.

Returns nothing.

```lua
reskate.on("throwdown_ui", function(e)
    if e.action == "open" and not ready then
        reskate.throwdowns.flag.leave() -- refuse: the setup page closes
    end
end)
```

<Note>Needs the `throwdowns` permission. When the plugin stops, its registration goes the same way.</Note>

## The `throwdown_ui` event

Fires for what the player does in the native throwdowns UI with one of your modes, and for the answers of your [dialogs](#dialogs).

```lua
reskate.on("throwdown_ui", function(e)
    reskate.log(e.mode .. ": " .. e.action .. " (" .. table.concat(e.args, ", ") .. ")")
end)
```

<ResponseField name="e.action" type="string">What happened: see the table.</ResponseField>
<ResponseField name="e.mode" type="string">Your mode's `id`. Empty for `dialog`, and may be empty for `quit`.</ResponseField>
<ResponseField name="e.args" type="table">A list of strings. Read numbers with `tonumber`.</ResponseField>

| `action` | When | `args` |
| --- | --- | --- |
| `open` | The player clicked your card, and the native flag began. | `{game}` |
| `setup_row` | A slider or a choice on the setup page changed. | `{row id, value}`. The stock rows' ids are `"players"` and `"timer"`. A slider's value is a whole number; a choice's is its option **counted from 0**. |
| `setup_button` | A button row on the setup page was pressed. | `{row id}` |
| `setup_back` | The player backed out of the setup page. The registration has gone. | `{game}` |
| `setup_confirm` | The player confirmed the setup page; flag placement opens. | `{players, seconds}`, as the page left them. |
| `flag_placed` | The start flag was placed. Publish the `waiting` card. | `{game, x, y, z, yaw}`: where it stands, and its facing in degrees. |
| `flag_left` | The registration ended without your `flag.leave()`: placement was cancelled or timed out, the map or session changed, a Leave finished, or nothing was published to keep it. | `{game}` |
| `start` | The waiting card's Start. | `{game}` |
| `leave` | The waiting card's Leave. The registration goes; `flag_left` follows unless you call `flag.leave()`. | `{game}` |
| `quit` | The match panel's Quit, or the pause menu's Quit Match while your `match` asks for `markers`. | `{}` |
| `join` | The player joined one of your flags with the game's Join. Their game now holds the registration: publish the `waiting` card. | `{flag id, leader, game}` |
| `panel_open` | The player opened the match panel. | `{}` |
| `panel_command` | The player pressed a panel prompt's input. | `{command}` |
| `dialog` | The player answered one of your dialogs. | `{dialog id, button, text, row, file text}` |

Events wait in a queue of 64 for each plugin; past that, the oldest go. An event has at most 16 args.

Registering a handler needs the `throwdowns` permission. See [events](/plugins/events).

### Dialogs

[`reskate.ui.dialog`](/plugins/api/menu#dialogs) (which needs `ui.screen` and `throwdowns`) answers through this event, with `action` `"dialog"` and an empty `mode`:

- `dialog id`: the dialog's id.
- `button`: the id of the button pressed; `"row"` for a list row clicked; a row button's name; `"file"` for a file opened; `"file_error"` when the file could not be read; `"cancel"` for Esc or B, which also closes the dialog.
- `text`: the text field's text. With `"file_error"`, why: `"the file cannot be read"` or `"the file is larger than 64 KB"`.
- `row`: the list row picked, from 1; `"0"` for none.
- `file text`: the opened file's text, at most 64 KB; empty otherwise.

## The `throwdown` event

Fired when a throwdown starts or ends for the local player, whoever hosted it.

```lua
reskate.on("throwdown", function(event)
    if event.phase == "started" then
        reskate.hud.hide(true)
    else -- "ended"
        reskate.hud.hide(false)
    end
end)
```

<ResponseField name="phase" type="string">`"started"` or `"ended"`.</ResponseField>

Registering a handler needs the `throwdowns` permission. See [events](/plugins/events).

<Tip>
While a throwdown runs, `reskate.skater.wipeout` and `reskate.animation.play` are refused, and trick replacements do not play. See [skater](/plugins/api/skater) and [animation](/plugins/api/animation).
</Tip>
